# Коммерческая приёмка калькулятора — вопросы владельцу

**Статус:** коммерческие правила ожидают подтверждения владельца. Этот документ фиксирует фактическую реализацию и вопросы; ставки, fixture и вычисления приложения на этом этапе не менялись.

## Краткий вывод

- Калькулятор проекта выдаёт только предварительный подытог строк с известными для разработки ставками. Полная смета и её соответствие коммерческим правилам не подтверждены.
- Девять ставок имеют статус `CONFIRMED_FROM_QUOTATION`: они встречаются в смете application no. 1, но это не подтверждение актуального официального прайса.
- Восемь ставок — `TEMPORARY_PLACEHOLDER`, разрешённые владельцем только для разработки. Остальные 19 видимых исходных вариантов — `UNVERIFIED` и без тарифа.
- Причина исходных 26 м обнаружена: публичный скрипт рассчитывает показатель, подписанный «периметр», по формуле `площадь × 1,3`. Для 400 × 500 см это 20 × 1,3 = 26 м. Это не геометрический периметр прямоугольника (18 м). Коммерческое применение эвристики не подтверждено.
- В fixture известна разница 0,10 PLN между суммой двух подытогов и указанным итогом. Причина неизвестна, а видимые округлённые количества и цены не позволяют однозначно воспроизвести подытоги.

## Фактическая логика приложения и проверки

### Конфигурация и сохранение

- Параметры: длина/ширина (целые сантиметры), материал (6 общих вариантов), образец цвета (визуальный выбор), профиль (4 варианта), количество каждой из 6 опций освещения, тип карниза (3 варианта или «без карниза»), шаг мастера.
- Визуализатор получает материал/цвет, профиль, свет и карниз из того же состояния калькулятора. Цвет влияет только на визуализацию и не является отдельной строкой сметы.
- Валидация размеров требует положительные целые безопасные числа; UI не задаёт максимальную границу. Ввод дробных сантиметров отклоняется. Счётчик света хранит целые значения ≥ 0, без прикладного максимума.
- `sessionStorage` с ключом `sufitowski-calculator-state-v1` сохраняет версию, шаг и все перечисленные выборы; восстановление работает в той же вкладке, включая переход между локалями. Между браузерами/устройствами данные не синхронизируются.

### Создаваемые строки и денежная арифметика

- Полотно: точная площадь `lengthCm × widthCm` в см² переводится в м² рационально. Мат/глянец/сатин используют только соответствующие временные ставки. Чёрный глянец, печать и «звёздное небо» остаются без цены.
- Профиль: выбранная опция выводится строкой `UNVERIFIED`; длина и сумма не рассчитываются. Ни геометрический периметр, ни эвристика исходного сайта не копируются.
- Свет: каждая положительная безопасная целая величина создаёт строку. Стандартный точечный светильник оценивается по временным 120 PLN/шт.; другие пять вариантов остаются без цены. Отдельная подтверждённая ставка монтажа освещения в смете в расчёт автоматически не добавляется.
- Карниз: выбранный тип создаёт строку без метража и суммы, так как UI не собирает длину и сопоставление с quotation price не подтверждено.
- Сумма считается в целых grosz с `BigInt`. Если деление даёт долю гроша, округление не выполняется: сумма строки и подытог становятся недоступны. Это осторожное техническое поведение, а не подтверждённое коммерческое правило. Полная сумма всегда имеет `isComplete: false`.

### Существующее покрытие

- В `package.json` указана команда `npm run verify:quotation` для независимой арифметики fixture: сумма подытогов 7 471,90 PLN, разница 0,10 PLN, 39,85 × 100 и × 90 PLN/м²; исходный JSON не меняется.
- Отдельного автоматического unit/e2e набора (Vitest/Jest/Playwright) нет. Проверка fixture не доказывает коммерческую эквивалентность.
- Зафиксированы прошлые lint/typecheck/build, проверка fixture и ручные smoke-сценарии; в ходе этого документального аудита повторные тесты не запускались.
